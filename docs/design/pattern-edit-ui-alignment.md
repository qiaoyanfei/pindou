# 拼豆图纸编辑页 · 产品 / UI 设计对齐文档

> 用途：与产品、UI 共同确定编辑页最终交互与视觉稿。  
> 范围：微信小程序「编辑图纸」全屏页（进入预览后点编辑）。  
> 更新日期：2026-08-02  
> 状态：待评审定稿

---

## 1. 页面目标

用户在生成/预览后的图纸上做**精细修改**，核心能力：

1. 看清格子与色号，对照原图修正  
2. 取色 → 画笔涂色 / 橡皮擦除  
3. 同色批量替换  
4. 缩放、移动查看细节  
5. 修改可撤销、可保存返回预览  

**非目标**：选区框选、复杂图层合成、多画笔笔刷样式。

---

## 2. 当前信息架构（已实现骨架）

### 2.1 布局分区

| 区域 | 内容 | 备注 |
|------|------|------|
| 顶栏 | 「完成」+ 规格标题（如 `52×52 · 编辑图纸`） | 自定义导航，避开右上角胶囊 |
| 主画布 | 图纸 / 对照 / 原图 | 全屏可缩放平移 |
| 底栏工具 | 取色、画笔、色板、橡皮、图层、撤销 | 固定底部 |
| 底栏提示 | 一行操作说明 | 随工具/图层变化 |
| 色板浮层 | brush 模式色号选择 | 底部 Sheet |

### 2.2 三个图层

| 图层 | 显示 | 可涂色 | 取色 |
|------|------|--------|------|
| 图纸 | 仅拼豆格 | ✅ | 取格子色号 |
| 对照 | 原图 + 半透明图纸叠加 | ✅ | 有色取图纸；空白取下层原图匹配色号 |
| 原图 | 仅原图（与图纸裁剪区对齐） | ❌ 画笔/橡皮灰置 | ✅ 点像素匹配最近色号 |

图纸规格为正方形（如用户选 52 → `52×52`），内容按原图比例**居中**，四周可为空白格。

### 2.3 四个主工具 + 色板

| 控件 | 作用 |
|------|------|
| 取色 | 点按取色；取色后默认切到画笔（原图层取色可保持取色工具） |
| 画笔 | 滑动/点击着色为当前色板色 |
| 色板 | 打开色号选择；原图层也可先换色 |
| 橡皮 | 滑动/点击擦成空白格 |
| 图层 | 图纸 → 对照 → 原图 循环 |
| 撤销 | 撤销上一笔或一次批量替换 |

默认进入工具：**浏览（平移）**，不是画笔——避免误涂。

## 3. 手势设计（核心争议点）

微信小程序**无法关闭** iOS/部分安卓的边缘滑动返回；业务侧只能做手势分流，不能「识别用户到底想拖还是想涂」到 100%。

### 3.1 当前实现（开发中状态）

| 场景 | 单指 | 双指 | 其它 |
|------|------|------|------|
| 浏览 | 拖动画布 | 缩放/拖动 | 双击格子 → 同色批量换成画笔色 |
| 画笔 / 橡皮 | 滑动涂/擦；**长按约 0.2s 后拖**可临时挪画布 | 缩放/拖动 | 双击同色批量替换 |
| 取色 | 轻点取色（移动超阈值则取消） | 缩放/拖动 | — |

### 3.2 已知问题（需产品和 UI 拍板）

**问题 A：单指「拖画布」与「滑动着色」天然冲突**

- 长按再拖：只能覆盖「先停再拖」的用户，**无法覆盖「一按就滑着想挪图」**  
- 方向/速度猜测：与水平涂色同形，误判高，不建议当主方案  

**问题 B：边缘从左往右大滑**

- 可能触发系统返回退出编辑页  
- 技术上无法可靠拦截；已做：笔画被打断时尽量提交、立即落盘，降低丢改风险  

**问题 C：双击同色替换 vs 单击涂一格**

- 画笔下第一击会先涂一格，第二击同格才批量替换  
- 需确认是否接受，或改为「仅浏览模式双击」/「独立桶填工具」

## 4. 待产品 / UI 决策的方案

请在评审会上对下列选项做 **单选或组合定稿**，作为 UI 终稿依据。

### 决策 1：画笔模式下如何移动画布？（必选）

| 方案 | 说明 | 误涂风险 | 学习成本 | 推荐 |
|------|------|----------|----------|------|
| **A. 工具互斥** | 画笔=只涂；挪图必须切回浏览，或**双指**拖 | 最低 | 低 | ⭐ 推荐主方案 |
| **B. 长按拖（现状）** | 画笔下长按后单指可拖 | 中（想拖却滑会涂） | 中 | 可作辅助，不宜单独依赖 |
| **C. 画布锁定开关** | 「锁定」开：单指只涂；关：单指可拖 | 低（用户显式选择） | 多一个控件 | 适合进阶用户 |
| **D. 延迟落笔** | 滑动超过 N 像素才开始涂 | 中低 | 涂色变钝 | 不推荐主方案 |

**建议文案方向（若选 A）**

- 提示：「画笔时双指移动图纸 / 点浏览后再拖」  
- 底栏可增加「手」或「移动」工具图标，与画笔并列，状态更清晰

## 5. UI 稿需覆盖的页面状态（出图清单）

请 UI 至少产出以下状态，便于开发对照验收：

1. **默认进入**（浏览工具 + 图纸图层）  
2. **画笔激活**（工具高亮 + 色板色号展示）  
3. **橡皮激活**  
4. **取色激活**  
5. **对照图层**（半透明叠加示意）  
6. **原图层**（画笔/橡皮禁用态）  
7. **色板 Sheet 打开**（brush 模式）  
8. **双击/桶填反馈**（若保留：toast 或短暂高亮）  
9. **撤销可用 / 不可用**  
10. **空状态**（无图纸数据，极少见）  
11. **操作提示条**文案规范（勿过长，建议 ≤ 18 字或两行上限）  

若选「画布锁定」或「独立油漆桶」，请追加对应激活态。

## 6. 文案与可达性建议

| 位置 | 建议原则 |
|------|----------|
| 底栏标签 | 二字为主：取色 / 画笔 / 色号 / 橡皮 / 图层 / 撤销 |
| 提示条 | 只说当前模式下一件最重要的事；手势教学可首次引导后弱化 |

## 7. 平台约束（设计时必须接受）

1. **不能真正全屏**：右上角微信胶囊始终存在，顶栏需避让。  
2. **不能禁用边缘右滑返回**：编辑页可能被误滑退出；保存策略需容忍（自动落盘）。  
3. **大图性能**：高规格（如 300 边）涂色依赖局部预览，不宜要求「每笔都整图闪新」。  
4. **手势优先级**：原生返回 > 业务触摸；边缘热区不适合做强依赖操作。
